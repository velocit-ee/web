the problem

small orgs deserve solid infrastructure. they just can't afford to maintain it.

[01]

bus factor of one

One person built it, understands it, maintains it. When they leave — graduation, another job, retirement — the knowledge walks out with them.

[02]

enterprise tools, enterprise price

The platforms that exist were built for Comcast, not a school or community ISP. Small orgs don't have $50k/yr infrastructure budgets.

[03]

fragile by default

Manually configured systems have no memory. When hardware dies or a rebuild is needed, there's no source of truth — just undocumented configs and someone's fading memory.

[04]

no handoff path

There's no standard way to hand a network off. No documentation, no rebuild script, no source of truth. Every transition is a crisis waiting to happen.

how it works

describe your hardware. get your config. run one command.

AI-assisted config generation — answer a survey or describe your setup in plain text. velocit.ee generates a complete, ready-to-run config bundle. no guesswork, no templates to reverse-engineer.

modular by design — four independent engines: metal provisioning, networking, services, lifecycle. already have Proxmox running? skip VME. already have networking? skip VNE. enter the pipeline wherever you are.

self-documenting — every engine writes a handoff manifest. the lifecycle engine turns those into human-readable documentation automatically. a new admin with zero context can pick up exactly where the last one left off.

built to be rebuilt — every config is reproducible. drift is detected. repair is a single command. the network doesn't depend on anyone's memory.

the long game

one engine at a time. each phase ships when it's solid.

01

VME — metal provisioning engine — now

PXE boot any x86_64 hardware, install Proxmox VE or Ubuntu Server fully unattended, write a handoff manifest, tear down the seed stack. first public release. this is the foundation everything else builds on.

02

VNE — network configuration engine

Consume the VME handoff manifest and build the network layer. OPNsense on Proxmox, VLANs, DHCP, DNS, baseline firewall. automated connectivity verification before handoff. join-existing path follows after build-new is solid.

03

VSE — services configuration engine

Deploy and configure a catalog of services on the verified network. containerized, idempotent, driven entirely by your config bundle. service catalog defined by what real orgs actually run.

04

VLE — lifecycle engine + beyond

Monitoring, auto-documentation, drift detection, single-command repair. this is what makes the tagline true. after VLE ships: cloud-hosted remote deployment, expanded hardware support, and eventually — infrastructure that scales all the way up.
